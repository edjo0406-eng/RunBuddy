---
name: RunBuddy-first product direction
description: Product hierarchy decision for the RunMatch community app.
---

RunBuddy is the main entry point and should receive the strongest homepage, navigation, and mobile emphasis. RunDate remains available as a secondary experience rather than the default identity. The homepage and browsing pages must remain publicly visible; require sign-in only for private actions such as joining, inbox, and messaging.

**Why:** The product should foreground finding running companions for local and travel runs, instead of presenting dating as the primary use case. Visitors opening the app URL need to see the product before deciding to sign in.

**How to apply:** Future homepage, navigation, onboarding, copy, and promotional changes should lead with RunBuddy unless the user explicitly asks for a RunDate-focused experience. Never wrap the entire frontend router in an authentication gate.
